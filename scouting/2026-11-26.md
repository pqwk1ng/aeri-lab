## Karpathy LLM Wiki（概念 + 三个实现）

实现：Astro-Han/karpathy-llm-wiki ★2,806、atomicstrata/llm-wiki-compiler ★2,278、sdyckjq-lab/llm-wiki-skill ★2,606。

- 三动作：Ingest（材料进 raw/，当场编译进 wiki/ 持久页）/ Query（只查 wiki 页、带引用回答）/ Lint（定期查死链、矛盾、过期）。
- 与普通 RAG 的根本区别：综合发生在写入时而非提问时，知识复利；代价是错误会被固化，需 Lint + 可追溯兜底。
- 可借鉴细节：置信度标签（EXTRACTED / INFERRED / AMBIGUOUS / UNVERIFIED）、「对话结晶」。

## openai/openai-agents-python ★30,883

- Agent = instructions + tools + guardrails + handoffs 四件套打包。
- Handoffs（移交主导权）与 Agents-as-tools（当工具调用）是两种不同的委派，别混用。
- Human-in-the-loop 是一等公民；Tracing 是标配——每次运行一条完整可回放的线，这是很多自研 agent 系统最缺的一块。

## langgenius/dify ★161,937

- 设计姿势：能确定的步骤走确定性节点，不确定的才交给模型。
- 抽样近期 issues，痛点几乎全在边角一致性：导入丢节点位置、必填校验被绕过、工具不校验输入 schema。
  结论：流程系统的痛不在主干，在导入导出、校验和状态一致性——边角一致性 > 功能数量。

## karpathy/autoresearch ★100,640 + nanochat ★60,903

- 自治实验闭环刻意做小：评估文件永不修改、agent 只能改一个文件、人只写 program.md 指令。
  固定时间预算 + 单一指标决定保留还是回滚。
- 对一切「让 agent 自我改进」的系统都成立的三条纪律：可改范围最小化、评估与被改对象分离、预算固定让结果可比。
